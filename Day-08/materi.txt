# 🛡️ DAY 8 — WINDOWS USER CONTEXT & PRIVILEGES

### Process siapa yang menjalankan? Account apa yang digunakan? Seberapa tinggi privilege-nya?

Day 7 kita sudah bisa menjawab:

> **Process apa yang berjalan? Siapa parent-nya? File executable-nya di mana? Dan dijalankan dengan command apa?**

Sekarang kita tambahkan satu pertanyaan penting:

> **“Process ini berjalan atas nama siapa?”**

Karena dalam SOC, `powershell.exe` yang dijalankan oleh **user biasa** bisa memiliki konteks berbeda dengan `powershell.exe` yang berjalan sebagai **SYSTEM** atau account berprivilege tinggi.

Hari ini kita belajar **User Context** dan dasar **Privileges**.

---

---

# 2. WINDOWS USER ACCOUNT

Di Windows ada berbagai account/context.

Contoh sederhana:

```text
Buya
Administrator
SYSTEM
LocalService
NetworkService
```

Kita belum perlu menghafal semuanya secara mendalam.

Yang penting sekarang:

> **Process berjalan dalam suatu security context/account.**

Misalnya:

```text
powershell.exe
User: Buya
```

berbeda konteks dengan:

```text
powershell.exe
User: SYSTEM
```

Keduanya sama-sama `powershell.exe`, tetapi **security context-nya berbeda**.

---

# 3. USER ≠ PROCESS

Ini sama seperti konsep Service vs Process.

Jangan mencampurkan:

```text
User
Process
Service
```

Contoh:

```text
User:
Buya

Process:
powershell.exe

PID:
8120
```

Artinya:

> Account `Buya` memiliki/menjalankan process `powershell.exe` tersebut dalam konteks user tersebut.

User bukan process.

---

# 4. APA ITU PRIVILEGE?

**Privilege** adalah permission/ability tertentu yang dimiliki security context.

Sederhananya:

```text
Low privilege
     ↓
akses terbatas

Higher privilege
     ↓
akses lebih besar
```

Contoh sederhana:

User biasa mungkin tidak bisa melakukan beberapa administrative actions.

Sedangkan Administrator atau SYSTEM memiliki kemampuan lebih besar terhadap operating system.

Jadi SOC harus peduli ketika misalnya:

```text
Normal user
    ↓
suddenly launches
    ↓
high-privilege process
```

Karena context tersebut bisa menjadi penting dalam investigation.

Tetapi sekali lagi:

> **High privilege ≠ malicious.**

Administrator dan Windows system components memang membutuhkan privilege tinggi.

---

# 5. KENAPA USER CONTEXT PENTING DALAM SOC?

Bayangkan ada:

```text
powershell.exe
PID 8000
```

Nama process saja belum cukup.

Kita perlu mengetahui:

```text
Who?
  ↓
Which account?
  ↓
What parent?
  ↓
What command?
  ↓
What file?
```

Misalnya:

```text
explorer.exe
    ↓
powershell.exe
    ↓
User: Buya
```

berbeda konteks dengan:

```text
services.exe
    ↓
powershell.exe
    ↓
User: SYSTEM
```

Kita belum mengatakan salah satu pasti malicious.

Kita mengatakan:

> **The security context is different, therefore the investigation context is different.**

# 6. COMMAND — CURRENT USER

Command yang sudah kamu kenal sejak Day 1:

```cmd

```

Contoh:

```text

```

Tujuannya:

> melihat identity/security context dari session yang sedang kamu gunakan.

---

# 7. COMMAND — CURRENT USER + GROUPS

Sekarang:

```cmd
whoami /groups
```

Ini akan menampilkan groups yang terkait dengan security context kamu.

Misalnya ada group seperti:

```text
BUILTIN\Administrators
BUILTIN\Users
```

Jangan langsung menganggap semua group berarti unrestricted access.

Hari ini cukup pahami:

> **Groups help determine what permissions/privileges a security context may have.**

# 8. MELIHAT USER YANG MENJALANKAN PROCESS

Sekarang kita masuk ke bagian yang lebih penting.

PowerShell:

```powershell
Get-Process -IncludeUserName |
Select-Object ProcessName, Id, UserName
```

Perhatikan:

```text
ProcessName
Id
UserName
```

Contoh:

```text
ProcessName   Id      UserName
-----------   --      --------
firefox      20516   LAPTOP\Buya
```

Sekarang process investigation kita sudah berkembang.

Sebelumnya:

```text
Process → PID → PPID
```

Sekarang:

```text
Process → PID → PPID → User
```

---

# 9. GABUNGKAN DENGAN PROCESS INVESTIGATION

Kita sebelumnya mendapatkan:

```text
powershell.exe
PID 18636
PPID 7476
```

Sekarang kita ingin mengetahui:

> **Who is running PID 18636?**

Kamu bisa menggunakan:

```powershell
Get-Process -Id 18636 -IncludeUserName |
Select-Object ProcessName, Id, UserName
```

Kalau PID tersebut sudah tidak ada, tentu command bisa gagal karena process-nya sudah 종료/exit.

Ini kembali ke pelajaran Day 7:

> **Processes are dynamic.**

# 10. USER CONTEXT + PROCESS TREE

Sekarang mental model kita:

```text

      ↓

```

Kita bisa bertanya:

> What is the parent?

> What command was used?

Itulah **context correlation**.

# 18. ATTACK METHOD — PRIVILEGE ABUSE

Sekarang sedikit pengenalan cybersecurity.

Salah satu tujuan attacker dalam banyak attack chain adalah memperoleh **higher privileges**.

Secara konsep:

```text
Normal User
    ↓
Exploit / Abuse
    ↓
Higher Privilege
```

Tujuan attacker bisa berupa kemampuan mengakses resource yang sebelumnya tidak dapat diakses.

Ini disebut:

> **Privilege Escalation**

Tetapi hari ini kita **belum belajar teknik privilege escalation secara praktis**.

Kita hanya membangun kemampuan mendeteksi **security context**.

```text

+

+

+

```

Contoh:

```text

      ↓

      ↓

      ↓

```

Itu memberikan investigator lebih banyak context dibanding hanya melihat:

```text

```

Jadi:

> **Context is more valuable than process name alone.**
