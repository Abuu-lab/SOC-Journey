# 3. PRAKTIK 3 ✅

Kamu menemukan:

```text
dllhost.exe
PID 9524
PPID 1600

ExecutablePath:
C:\WINDOWS\system32\DllHost.exe

CommandLine:
"C:\WINDOWS\system32\DllHost.exe" /Processid:{...}
```

Lalu kamu berkata:

> executablepath sepertinya gak penting, soalnya di CommandLine sudah termasuk ada ExecutablePath

🟡 **Ini pemahaman yang perlu diluruskan.**

Memang dalam contoh ini CommandLine **kebetulan memuat path executable**, tetapi `ExecutablePath` tetap berguna.

Kita punya dua data berbeda:

```text
ExecutablePath
→ properti lokasi executable

CommandLine
→ bagaimana process dijalankan + arguments
```

Misalnya:

```text
ExecutablePath:
C:\Windows\System32\powershell.exe
```

CommandLine:

```text
powershell.exe -ExecutionPolicy Bypass -File C:\Temp\a.ps1
```

CommandLine bisa memberi informasi lebih banyak tentang **invocation**, sementara `ExecutablePath` memberi kita lokasi executable secara langsung.

Jadi jangan buang `ExecutablePath`.

### Q6 Service vs Process 🔴 kecil tapi penting

Kamu masih menulis:

> service menghasilkan process

Nah, ini **masih kesalahan Day 5 yang muncul lagi**, jadi aku akan bawa ke Active Recall Day 8.

Jangan gunakan:

```text
Service → menghasilkan → Process
```

Gunakan:

```text
Service
↕
associated with
Process
```

atau contoh:

```text
Dhcp Service
     ↓
ProcessId 2300
     ↓
svchost.exe
```

Service memiliki informasi `ProcessId` yang menunjuk kepada process yang terkait saat service berjalan.

**Service ≠ Process.**

### Q3 ExecutablePath 🟡

Kamu mengatakan relationship `explorer → powershell` mencurigakan karena jarang kamu lihat.

Hati-hati di sini.

**Jangan menggunakan “jarang aku lihat” sebagai bukti utama.**

Yang bisa kita katakan dari data:

```text
Parent:
explorer.exe

Executable:
C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
```

Itu menunjukkan PowerShell dijalankan dari lokasi executable Windows yang terlihat normal.

Relationship `explorer.exe → powershell.exe` **sendiri belum membuktikan malicious activity**.

Ini bagus untuk reminder:

> **Unfamiliar ≠ Malicious**

---

### Q4 `-ExecutionPolicy Bypass` ✅/🟡

Kamu mengatakan:

> bypass itu sangat mencurigakan

Lebih tepat:

> `-ExecutionPolicy Bypass` adalah **suspicious indicator/context** yang layak diinvestigasi lebih lanjut.

Jangan langsung:

```text
Bypass = malware
```

Karena legitimate administrators/scripts juga dapat menggunakan PowerShell configuration tertentu.

Namun dalam kombinasi dengan:

```text
-ExecutionPolicy Bypass
+
Temp script
+
suspicious parent/context
```

kita punya alasan yang lebih kuat untuk mencari evidence tambahan.

# 7. MINI SOC REPORT

Kamu menemukan:

```text
winlogon.exe
PID 2688
PPID 16548
```

dan saat mencari PID `16548`, tidak mendapatkan hasil.

Ini **bukan masalah**.

Satu kemungkinan sederhana:

> parent process bisa sudah exit sebelum query kedua dilakukan.

Process adalah dynamic.

Misalnya:

```text
20:00:01
PID 16548 masih ada

20:00:05
kamu query

PID 16548 sudah exit
```

Maka query tidak menemukan process tersebut.

Ini memberi kita pelajaran baru:

> **Process investigation terjadi terhadap sistem yang terus berubah.**

Jadi:

```text
No result
≠
Process never existed
```

dan:

```text
Missing data
≠
Data never existed
```

Ini sama dengan prinsip yang sudah kita pelajari sebelumnya.
