WINDOWS EVENT TIMELINE & CORRELATION

### Time • Event Sequence • Correlation • Historical Investigation

Day 9 kita belajar:

> **Event Log = historical evidence**

Hari ini kita belajar bagaimana **menghubungkan beberapa event berdasarkan waktu**.

Ini penting karena satu event sendirian sering tidak cukup.

Contoh:

```text
20:01
4625 — Failed Logon

20:03
4688 — Process Created

20:04
7045 — Service Installed
```

Masing-masing event bisa terlihat biasa atau belum cukup jelas.

Tetapi ketika disusun berdasarkan waktu, kita mulai mendapatkan **story**.

# 1. REVIEW KONSEP DAY 9

Ada beberapa hal dari Day 9 yang masih salah dan **wajib kita perbaiki hari ini**.

### Reminder 1 — `ExecutablePath` vs `CommandLine`

Ingat:

```text
ExecutablePath → WHERE?
CommandLine    → HOW?
```

Contoh:

```text
ExecutablePath:
C:\Windows\System32\powershell.exe
```

CommandLine:

```text
powershell.exe -ExecutionPolicy Bypass -File C:\Temp\test.ps1
```

`CommandLine` menjelaskan bagaimana process dijalankan, termasuk arguments.

---

### Reminder 2 — Service ≠ Process

Jangan lagi:

> service menghasilkan process.

Gunakan:

```text
Service
   ↓
has/associated with
   ↓
ProcessId
   ↓
Process
```

Contoh:

```text
Dhcp Service
     ↓
ProcessId 2300
     ↓
svchost.exe
```

---

### Reminder 3 — Digital Signature

Digital Signature digunakan untuk memeriksa **signature pada file/executable**, bukan menentukan apakah "process valid".

```text
Valid Signature
      ≠
Automatically Safe
```

---

### Reminder 4 — Security Context

**Security Context** secara sederhana adalah identity + groups + privileges yang digunakan oleh sebuah account/process ketika melakukan action.

Contoh:

```text
User:
Buya
```

dan:

```text
User:
NT AUTHORITY\SYSTEM
```

mempunyai context yang berbeda.

---

### Reminder 5 — Current State vs Historical Evidence

```text
Get-Process
    ↓
What is happening NOW?
```

Sedangkan:

```text
Get-WinEvent
    ↓
What happened?
```

---

### Reminder 6 — Timestamp

`TimeCreated` pada event membantu kita mengetahui **kapan event tersebut terjadi/tercatat**.

Jangan menyamakan:

```text
Event Time
```

dengan:

```text
File CreationTime
```

# 3. APA ITU TIMELINE?

Timeline adalah urutan event berdasarkan waktu.

Format paling sederhana:

```text
EARLIEST
   ↓
Event A
   ↓
Event B
   ↓
Event C
   ↓
LATEST
```

Contoh:

```text
20:01:10
4624 — Successful Logon

20:03:22
4688 — PowerShell Created

20:03:25
4688 — Another Process Created

20:04:10
7045 — Service Installed
```

Itulah timeline.

---

# 4. APA ITU CORRELATION?

**Correlation** berarti mencari hubungan antara evidence.

Misalnya:

```text
Event 4688
PowerShell created
       ↓
same user
       ↓
same time window
       ↓
Event 7045
Service installed
```

Kita belum mengatakan malicious.

Kita hanya mengatakan:

> **These events may be related and require further investigation.**

---

# 5. EMPAT PERTANYAAN DASAR TIMELINE

Ketika melihat timeline, tanyakan:

### WHO?

Siapa account/user?

### WHAT?

Apa yang terjadi?

### WHEN?

Kapan terjadi?

### RELATIONSHIP?

Apakah event-event tersebut mungkin berhubungan?

Nanti kita tambah:

```text
WHERE?
HOW?
```

# 7. PRAKTIK — AMBIL EVENT BERDASARKAN WAKTU

Sekarang kita mulai mencari event dalam **time window** tertentu.

Gunakan:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='System'
    StartTime=(Get-Date).AddDays(-1)
} -MaxEvents 20 |
Select-Object TimeCreated, Id, ProviderName, LevelDisplayName, Message
```

Artinya secara sederhana:

```text
System log
↓
24 jam terakhir
↓
20 event
```

# 10. FILTER WAKTU LEBIH SPESIFIK

Kita bisa menentukan:

```text
StartTime
EndTime
```

Contoh:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='System'
    StartTime=(Get-Date '2026-09-28 13:00:00')
    EndTime=(Get-Date '2026-09-28 14:00:00')
} |
Select-Object TimeCreated, Id, ProviderName, LevelDisplayName, Message
```

Ini berarti:

> hanya cari event antara 13:00 dan 14:00.

Ini sangat berguna saat melakukan investigation terhadap **specific time window**.

---

# 11. FILTER MULTIPLE EVENT ID

Kita juga bisa mencari beberapa Event ID.

Contoh:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='Security'
    Id=4624,4625
} -MaxEvents 20 |
Select-Object TimeCreated, Id, ProviderName, LevelDisplayName, Message
```

Sekarang kita mendapatkan:

```text
4624
4625
```

dalam satu query.

---

# 12. SORT TIMELINE

Kadang hasil event perlu kita urutkan.

Gunakan:

```powershell
Get-WinEvent -LogName System -MaxEvents 20 |
Select-Object TimeCreated, Id, ProviderName, Message |
Sort-Object TimeCreated
```

`Sort-Object TimeCreated` berarti:

> urutkan berdasarkan waktu.

Sekarang kamu mulai benar-benar membuat timeline.

# 14. JANGAN OVER-INTERPRET

Ini sangat penting untuk latihan ketelitianmu.

Timeline:

```text
4624
↓
4688
↓
7045
```

**Bukan otomatis:**

```text
attacker
↓
malware
↓
persistence
```

Itu sudah merupakan **interpretation** yang membutuhkan evidence.

Yang boleh kita katakan dari data sederhana:

> "A successful logon was recorded, followed later by process creation and service installation events."

Itu **observation**.

Lalu kita masuk investigation:

> Apakah event tersebut berhubungan?

Baru kemudian kita mencari evidence tambahan.

---

# 15. OBSERVATION vs INFERENCE vs CONCLUSION

Ini latihan penting untuk otak investigator.

### Observation

Apa yang benar-benar terlihat di data.

Contoh:

```text
7045
Service installed
```

### Inference

Kesimpulan sementara berdasarkan evidence.

Contoh:

> Service installation terjadi tidak lama setelah process creation.

### Conclusion

Assessment yang sudah didukung oleh evidence yang cukup.

Kita **belum belajar membuat final incident verdict** sekarang.

# 24. ATTACK METHOD — EVENT CORRELATION

Dalam real SOC, attacker bisa melakukan beberapa aktivitas berurutan.

Secara konsep:

```text
Initial Access
      ↓
Execution
      ↓
Persistence
      ↓
Network Activity
```

Masing-masing aktivitas bisa menghasilkan telemetry berbeda.

Misalnya:

```text
Process Event
    +
Service Event
    +
Network Event
```

SOC kemudian mencoba **correlate** evidence tersebut.

Namun jangan langsung menganggap:

```text
Process + Service + Network
=
Attack
```

Karena legitimate software juga menghasilkan process, service, dan network activity.

---

# 25. DEFENSE METHOD

Salah satu cara meningkatkan detection adalah memiliki **sufficient logging**.

Contoh:

```text
Process Creation
     ↓
Event Log

Authentication
     ↓
Event Log

Service Installation
     ↓
Event Log

Network Activity
     ↓
Network Telemetry
```

Semakin baik telemetry, semakin bagus kemampuan investigator untuk membuat timeline.

Inilah alasan nanti kita akan masuk ke:

```text
Windows Event Logs
       ↓
Sysmon
       ↓
Wazuh / SIEM
```

Tetapi **belum sekarang**. Kita masih memperkuat kemampuan membaca evidence mentah.
