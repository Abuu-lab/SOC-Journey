Berikut adalah penjelasan sederhana untuk 2 poin pertanyaan yang kamu tanyakan:

### Pertanyaan 3: Bagaimana Alur System Call (Syscall) Bekerja? (Analisis Restoran)

Aplikasi biasa di User Mode (seperti Notepad) **dilarang keras** langsung menyentuh harddisk atau memori.

---

Bayangkan **User Mode** adalah **Pelanggan Restoran**, dan **Kernel Mode** adalah **Dapur Restoran**:

1. **User Application (Notepad):** Kamu (Pelanggan) ingin menyimpan file. Kamu tidak boleh masuk langsung ke dapur memasak sendiri.
2. **System Call Interface (Pelayan/Waiter):** Kamu memanggil pelayan via fungsi Windows (`WriteFile` / `ntdll.dll`). Pelayan mencatat pesananmu ke dalam format standar (nomor **Syscall**).
3. **Transition (Pintu Dapur):** Pelayan membawa pesanan melewati pintu khusus (instruksi CPU `syscall`).
4. **Kernel Mode (Koki/Chef):** Koki di dapur menerima pesanan, memeriksa apakah kamu punya hak (*permission*), lalu menulis data langsung ke harddisk/SSD (**Hardware**).
5. **Return:** Koki memberitahu pelayan "Selesai", dan pelayan menyampaikan ke Notepad "File Berhasil Disimpan".

### Pertanyaan 8: Nomor Event ID untuk Service Baru & Kegunaannya

* **Windows Event ID 7045:** Mencatat setiap ada **Service Baru yang diinstall/dibuat** di dalam sistem.
* **Windows Event ID 7036:** Mencatat perubahan status service (misal: Service Defender berubah dari **RUNNING** menjadi **STOPPED**).

**Mengapa ini vital bagi SOC Analyst?**
Penyerang sering menggunakan Service sebagai metode **Persistence** (agar malware otomatis berjalan kembali setiap PC dinyalakan). Memantau Event ID 7045 memberikan peringatan dini (*alert*) saat ada service mencurigakan yang baru dibuat.
