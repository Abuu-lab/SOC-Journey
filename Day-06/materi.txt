# 🛡️ DAY 6 — FILE INVESTIGATION

### Hash • Digital Signature • Metadata

Hari ini kita naik satu langkah dari **Process Investigation (Day 3)** dan **Service Investigation (Day 5)**.

Di Day 6, fokus kita adalah:

> **Process → Executable → File → Metadata → Digital Signature → SHA-256**

Tujuan akhirnya bukan sekadar bisa menjalankan command, tetapi kamu mulai berpikir seperti SOC Analyst:

> **“File ini sebenarnya apa? Di mana lokasinya? Kapan dibuat/diubah? Siapa yang menandatangani? Fingerprint-nya apa?”**

---

# 1. REVIEW CEPAT DAY 5

Sebelum masuk materi baru, ingat kembali:

### Service ≠ Process

Contoh:

```text
Dhcp Service
      ↓
svchost.exe
PID 2300
      ↓
services.exe
PID 1424
      ↓
PID 1304
```

Lebih tepatnya hubungan prosesnya:

```text
PID 1304
   ↓
services.exe PID 1424
   ↓
svchost.exe PID 2300
```

Service **Dhcp** menggunakan/terkait dengan process `svchost.exe` PID `2300`.

### Ingat:

**PID**
→ ID untuk process saat ini.

**PPID**
→ nilai PID dari parent process.

**StartName**
→ account yang digunakan service.

**PathName**
→ executable path + kemungkinan arguments.

Contoh:

```text
C:\Windows\System32\svchost.exe -k LocalServiceNetworkRestricted -p
```

Bagian:

```text
C:\Windows\System32\svchost.exe
```

adalah executable.

Sedangkan:

```text
-k LocalServiceNetworkRestricted -p
```

adalah arguments.

# 3. FILE METADATA

**Metadata** adalah informasi mengenai sebuah file.

Contohnya:

* Name
* Length
* CreationTime
* LastWriteTime
* LastAccessTime

Misalnya:

```text
Name          : unknown.exe
Length        : 248832
CreationTime  : 2026-09-20
LastWriteTime : 2026-09-21
```

Informasi ini membantu kita memahami **context** file.

Misalnya file baru dibuat beberapa menit sebelum sebuah suspicious process muncul.

Itu bisa menjadi **additional evidence**.

Tetapi:

> **Metadata ≠ proof of malware**

Metadata membantu investigation, bukan memberikan verdict sendirian.

---

# 4. PRAKTIK 1 — FILE METADATA

Kita gunakan file Windows yang legitimate agar aman:

```text
C:\Windows\System32\svchost.exe
```

Jalankan PowerShell:

```powershell
Get-Item "C:\Windows\System32\svchost.exe" |
Select-Object Name, Length, CreationTime, LastWriteTime, LastAccessTime
```

Kamu akan mendapatkan informasi seperti:

```text
Name
Length
CreationTime
LastWriteTime
LastAccessTime
```

### Yang harus kamu pahami:

**Name**

Nama file.

**Length**

Ukuran file dalam bytes.

**CreationTime**

Waktu file dibuat.

**LastWriteTime**

Waktu terakhir file dimodifikasi.

**LastAccessTime**

Waktu terakhir file diakses, jika informasi tersebut tersedia/tercatat.

# 5. DIGITAL SIGNATURE

Sekarang kita naik satu level.

Windows menggunakan **Authenticode** untuk digital signatures pada executable tertentu.

Command:

```powershell
Get-AuthenticodeSignature "C:\Windows\System32\svchost.exe"
```

Perhatikan terutama:

```text
Status
SignerCertificate
```

Status bisa menunjukkan misalnya:

```text
Valid
NotSigned
UnknownError
HashMismatch
```

### Kalau `Valid`

Artinya signature dapat divalidasi berdasarkan mekanisme trust Windows.

Tetapi:

> **Valid signature ≠ pasti aman.**

Ini sangat penting untuk SOC.

Sebuah malicious file masih dapat menggunakan certificate yang valid, misalnya jika software berbahaya memang ditandatangani atau certificate yang sah disalahgunakan.

Jadi jangan berpikir:

```text
Valid = Safe
```

Gunakan:

```text
Valid = evidence
```

---

# 6. `NotSigned` JUGA BUKAN BERARTI MALWARE

Misalnya:

```text
Status : NotSigned
```

Jangan langsung:

> "Malware!"

Karena ada legitimate software yang memang tidak memiliki digital signature.

Jadi:

```text
Signed ≠ Automatically Safe
Unsigned ≠ Automatically Malicious
```

Ini adalah mindset penting dalam investigation.

---

# 7. SHA-256

Sekarang kita mencari **fingerprint** file.

Gunakan:

```powershell
Get-FileHash "C:\Windows\System32\svchost.exe" -Algorithm SHA256
```

Output akan memiliki:

```text
Algorithm
Hash
Path
```

Contoh bentuknya:

```text
Algorithm : SHA256
Hash      : A1B2C3D4...
Path      : C:\Windows\System32\svchost.exe
```

Hash adalah nilai yang dihasilkan berdasarkan isi file.

Kalau isi file berubah, hash biasanya berubah.

Jadi SHA-256 dapat membantu kita menjawab:

> **“File yang sedang saya investigasi ini fingerprint-nya apa?”**

---

### Digital Signature

Menjawab:

> **“Siapa yang menandatangani file ini dan apakah signature dapat divalidasi?”**

Contoh:

```text
Status: Valid
Signer: Microsoft Corporation
```

---

### SHA-256

Menjawab:

> **“Fingerprint file ini apa?”**

Contoh:

```text
SHA256:
A1B2C3D4...
```

Memory trick:

```text
Metadata   → FILE INFORMATION
Signature  → SIGNER / TRUST
SHA-256    → FINGERPRINT
```

**5.** Kalau ingin mengetahui kapan file dibuat/diubah, apa yang kamu periksa?

```text

```

