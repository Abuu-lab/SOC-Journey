# 8. PID vs PPID vs SHA-256 vs Signature vs Metadata

Jawabanmu sudah cukup bagus.

Tapi aku ingin kamu mengubah cara mengingatnya menjadi seperti ini:

### PID

> **ID untuk process saat ini.**

Contoh:

```text
firefox.exe
PID 5500
```

### PPID

> **PID milik parent process.**

Contoh:

```text
unknown.exe
PID 4216
PPID 5500
```

Artinya:

```text
unknown.exe
    ↓
PPID = 5500
    ↓
cari PID 5500
    ↓
firefox.exe
```

### SHA-256

> **Fingerprint berdasarkan content file.**

### Digital Signature

> **Informasi signature/certificate yang membantu memvalidasi publisher/signing identity dan integritas signature.**

### Metadata

> **Informasi tentang file.**

Misalnya:

```text
Name
Length
CreationTime
LastWriteTime
LastAccessTime
```

# 9. ⚠️ KOREKSI PENTING: VALID SIGNATURE

Kamu menjawab:

> "bisa saja peretas memilih credential atau meniru agar system mengira bahwa itu valid"

Konsep besarnya kamu sudah menangkap:

> **Valid signature tidak otomatis berarti aman.**

Tetapi jangan menghafal bahwa attacker **"meniru signature"**.

Lebih tepat:

> A malicious file can still have a valid digital signature, misalnya software malicious memang ditandatangani dengan certificate yang sah atau certificate yang sah disalahgunakan/dicuri.

Jadi:

```text
Valid
  ↓
Signature berhasil divalidasi
  ↓
BUKAN
  ↓
File pasti aman
```

Ini penting sekali untuk SOC.

### PathName

> **ExecutablePath = lokasi file executable yang dijalankan oleh process.**

Decide response

KILL!!!
