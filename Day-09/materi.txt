# 🛡️ DAY 9 — WINDOWS EVENT LOGS

### Event • Log • Event ID • Timestamp • Provider • Evidence

Day 1–8 kita banyak bekerja dengan **current system state**:

```text
Process
PID
PPID
User
ExecutablePath
CommandLine
Service
File
Metadata
Digital Signature
SHA-256
```

Sekarang kita mulai belajar sesuatu yang sangat penting untuk SOC:

> **Historical evidence — apa yang sudah terjadi di Windows.**

Karena process bisa sudah berhenti, user bisa sudah logout, atau file bisa sudah berubah. Dalam kondisi seperti itu, **Windows Event Logs** bisa memberikan jejak aktivitas yang terjadi sebelumnya.

---

# 1. APA ITU EVENT LOG?

Windows menyimpan berbagai aktivitas dalam bentuk **events**.

Contohnya:

```text
User login
Process creation
Service activity
System startup
Application error
Authentication failure
```

Event tersebut disimpan ke dalam **Event Logs**.

Contoh log utama:

```text
Application
Security
System
```

Ada juga log lain seperti:

```text
Windows PowerShell
Task Scheduler
Windows Defender
```

Hari ini kita fokus pada dasar-dasarnya.

---

# 2. EVENT LOG ≠ EVENT

Ini harus dibedakan.

### Event Log

Tempat/kumpulan event disimpan.

Misalnya:

```text
Security
System
Application
```

### Event

Satu record aktivitas.

Misalnya:

```text
Security Event
Event ID: 4625
Time: 20:15:32
```

Jadi:

```text
Event Log
   ↓
contains
   ↓
Events
```

---

# 3. KENAPA SOC MEMBUTUHKAN EVENT LOG?

Bayangkan tadi kita melihat:

```text
powershell.exe
PID 8120
```

Kemudian 5 menit kemudian process tersebut berhenti.

Kalau kita menjalankan:

```powershell
Get-Process
```

process tersebut mungkin sudah tidak terlihat.

Tetapi event log bisa menyimpan catatan bahwa sesuatu pernah terjadi.

Konsepnya:

```text
CURRENT STATE
Process masih berjalan?
        ↓
Get-Process
```

sedangkan:

```text
HISTORICAL EVIDENCE
Apa yang sebelumnya terjadi?
        ↓
Event Logs
```

Ini hubungan penting dengan Day 7.

---

# 4. EVENT LOG YANG HARUS KAMU KENAL

## Application

Berisi event dari aplikasi/software.

Contoh:

```text
Application crash
Application error
```

---

## System

Berisi event yang berhubungan dengan Windows/system components.

Contoh:

```text
Service
Driver
System startup/shutdown
```

---

## Security

Sangat penting untuk SOC.

Berisi security/auditing events seperti:

```text
Logon
Logoff
Authentication failure
Process creation
Account activity
```

Tetapi event yang muncul **bergantung pada audit policy dan konfigurasi Windows**.

Jadi:

> **Tidak semua Windows system akan memiliki semua security events.**

---

# 5. EVENT ID

Setiap event biasanya memiliki **Event ID**.

Contoh yang perlu mulai kamu kenal:

```text
4624
4625
4688
7045
```

Secara umum:

### 4624

Successful logon.

### 4625

Failed logon.

### 4688

Process creation.

### 7045

A service was installed.

Penting:

> Event ID bukan verdict.

Misalnya:

```text
4625
```

tidak otomatis berarti:

> attacker.

Bisa saja user salah memasukkan password.

Sama seperti:

```text
powershell.exe
```

tidak otomatis berarti malware.

Kita tetap membutuhkan **context + correlation**.

---

# 6. EVENT STRUCTURE

Sebuah event memiliki beberapa field penting.

Misalnya:

```text
Event ID
Provider
TimeCreated
Level
Message
```

Mari pahami.

### Event ID

Jenis event.

```text
4625
```

### Provider

Komponen/software yang mencatat event.

Contoh:

```text
Microsoft-Windows-Security-Auditing
```

### TimeCreated

Kapan event terjadi/tercatat.

### Level

Contoh:

```text
Information
Warning
Error
Critical
```

Jangan berpikir:

```text
Error = Security incident
```

Tidak selalu.

### Message

Penjelasan event.

# 7. COMMAND DASAR — GET-WINEVENT

PowerShell menyediakan:

```powershell
Get-WinEvent
```

Ini akan mengambil Windows events.

Kalau kamu hanya menjalankan:

```powershell
Get-WinEvent
```

output bisa sangat banyak.

Maka biasanya kita batasi berdasarkan log.

---

# 8. MELIHAT EVENT DARI SYSTEM

Gunakan:

```powershell
Get-WinEvent -LogName System -MaxEvents 10
```

Artinya:

```text
-LogName System
→ ambil dari System log

-MaxEvents 10
→ ambil 10 event terbaru
```

---

# 9. MELIHAT EVENT DARI APPLICATION

```powershell
Get-WinEvent -LogName Application -MaxEvents 10
```

---

# 10. MELIHAT EVENT DARI SECURITY

```powershell
Get-WinEvent -LogName Security -MaxEvents 10
```

Kalau muncul **Access Denied**, jangan panik.

Security log memiliki permission yang lebih ketat pada banyak sistem.

Kita lanjut dengan event log yang bisa kamu akses.

---

# 11. MEMILIH FIELD

Output default `Get-WinEvent` bisa terlihat penuh.

Gunakan:

```powershell
Get-WinEvent -LogName System -MaxEvents 10 |
Select-Object TimeCreated, Id, ProviderName, LevelDisplayName, Message
```

Sekarang kamu dapat:

```text
TimeCreated
Id
ProviderName
LevelDisplayName
Message
```

Ini jauh lebih berguna untuk investigation.

---

# 12. COMMAND — MELIHAT EVENT ID TERTENTU

Misalnya kita ingin mencari Event ID `7045`:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='System'
    Id=7045
} -MaxEvents 10
```

`7045` berkaitan dengan **service installation**.

Ini menarik karena Day 5 kita belajar:

```text
Service
Process
PID
PathName
```

Sekarang kita bisa melihat **historical record** tentang service activity.

---

# 13. COMMAND — 4624 / 4625

Untuk Security log:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='Security'
    Id=4624
} -MaxEvents 10
```

dan:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='Security'
    Id=4625
} -MaxEvents 10
```

Sekali lagi:

```text
4624 ≠ automatically good
4625 ≠ automatically attack
```

Kita perlu melihat:

```text
Who?
When?
Where?
What account?
How many attempts?
Source IP?
Logon type?
```

Belum semuanya kita pelajari hari ini. Kita akan menambahkannya secara bertahap.

---

# 14. EVENT 4688 — PROCESS CREATION

Ini sangat relevan dengan Day 7.

```text
Process Investigation
        ↓
PID / PPID / CommandLine
```

Event:

```text
4688
```

berhubungan dengan **a new process being created**.

Jalankan:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='Security'
    Id=4688
} -MaxEvents 10
```

Kalau tidak ada hasil, jangan menyimpulkan event tersebut tidak pernah terjadi.

Bisa saja:

> **process creation auditing belum enabled**, event log sudah berubah/terhapus, atau filtering/configuration berbeda.

Ini persis mengulang prinsip kita:

> **Missing data ≠ data never existed.**

# 15. CURRENT STATE VS HISTORICAL EVIDENCE

Sekarang kita punya dua dunia.

### Current state


> **What is happening now?**

```text

```

Memberi gambaran:

> **What happened?**

SOC Analyst membutuhkan keduanya.

# 27. ATTACK METHOD — FAILED AUTHENTICATION

Salah satu aktivitas yang bisa terlihat dalam Windows logs adalah **failed authentication**.

Contohnya:

```text
User attempts login
      ↓
Wrong password
      ↓
Authentication fails
      ↓
Event 4625
```

Defensive analyst mungkin akan melihat pola:

```text
4625
4625
4625
4625
4625
...
```

Kemudian bertanya:

> Berapa kali?

> Account siapa?

> Kapan?

> Dari mana?

> Apakah pattern tersebut normal?

Tetapi:

> **One 4625 ≠ Brute Force**

Satu user salah password sekali adalah sesuatu yang sangat berbeda dari banyak failed authentication attempts dalam waktu singkat.

Ini nanti akan menjadi dasar kita untuk belajar **Brute Force Detection**.

---

# 28. DEFENSE METHOD

SOC menggunakan **logging and monitoring** untuk mendapatkan historical evidence.

Konsepnya:

```text
Activity
   ↓
Windows
   ↓
Logging
   ↓
Event
   ↓
SOC
   ↓
Investigation
```

Tanpa logging yang cukup, investigator bisa kehilangan visibility.

Karena itu nanti kita akan belajar:

```text
Windows Event Logs
        ↓
Sysmon
        ↓
Wazuh / SIEM
```

Tapi kita **belum lompat ke Wazuh**.

Kita kuasai evidence source-nya dulu.
